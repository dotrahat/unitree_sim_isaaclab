Architecture · xr_teleoperate × unitree_sim_isaaclab × physical robot

How an operator in XR drives a Unitree G1, simulated or real

One teleop program, two interchangeable targets. teleop_hand_and_arm.py turns headset poses into joint commands and sends them over DDS, either to the Isaac Lab simulator (--sim, DDS domain 1) or to the physical G1 (default, DDS domain 0). Each target runs its own image server that streams camera video back to the operator.

The simulator publishes the same DDS topics as the real robot. The controllers make one decision, sim or physical, from the --sim flag. The DDS domain and the arm topic follow from that choice. The rest of the pipeline stays the same.

Shared · every tick

Headset pose → joint commands

  1. TeleVuer reads head, wrist and hand poses (hand tracking or controllers).
  2. Arm IK (robot_arm_ik.py) solves both arms; hand retargeting maps fingers to Dex3 / Inspire / BrainCo / Dex1 joints.
  3. Controllers check the target (--sim), then publish arm + hand commands and read back rt/lowstate and hand state.
  4. EpisodeWriter (--record) saves images, states and actions for training, from either target.

Target · simulation (--sim)

unitree_sim_isaaclab

  • DDS domain 1. Arms on rt/lowcmd, hands on rt/<hand>/…/cmd.
  • Inside sim_main.py: DDS bridge → action provider → RobotController.step() → Isaac Lab task.
  • Extras: rt/reset_pose/cmd resets the scene, rt/sim_state goes into recordings, rt/run_command/cmd sets walking velocity for whole-body tasks.
  • Task cameras → shared memory → sim image server.

Target · physical robot

Unitree G1

  • DDS domain 0 over the robot network (--network-interface).
  • --motion (normal use): arms on rt/arm_sdk, and the robot's own balance controller stays on.
  • --debug-mode: raw rt/lowcmd, with balance off.
  • Walking uses LocoClient / MotionSwitcher instead of rt/run_command/cmd.
  • Head cameras (UVC / RealSense) are served by teleimager on the robot's PC2.
